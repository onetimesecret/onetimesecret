### 1. Data model / store

#### 1.1 `apps/web/billing/models/stripe_webhook_event.rb` (add after `identifier_field :stripe_event_id`, line 60)

```ruby
    # ========================================
    # Newest-first index (#4347)
    # ========================================
    # member = stripe_event_id (String), score = first_seen_at epoch seconds.
    # Written ONCE per event, at the single first-save site
    # (Billing::WebhookValidator#initialize_event_record), trimmed to
    # MAX_INDEXED on every write. Records expire (default_expiration 5.days)
    # independently of this set, so readers MUST treat a member whose record no
    # longer loads as stale: skip it and lazily `unindex!` it. The index only
    # covers events received after this code shipped — there is NO backfill
    # (records live 5 days; a backfill would be stale before it finished).
    class_sorted_set :timeline

    MAX_INDEXED = 5_000

    # Fields the LIST projection reads (pipelined HMGET — never event_payload,
    # which can be tens of KB per row). Order matters: rows are built positionally.
    LIST_FIELDS = %w[
      stripe_event_id event_type processing_status livemode first_seen_at
      last_attempt_at processed_at attempt_count created data_object_id
      request_id error_message
    ].freeze

    class << self
      # Best-effort: the record is already saved; a failed index write must never
      # fail the webhook ingress (Stripe would retry a delivered event).
      def index!(event)
        timeline.add(event.stripe_event_id, event.first_seen_at.to_i)
        trim_timeline!
      rescue StandardError => ex
        Onetime.billing_logger.warn '[StripeWebhookEvent] timeline index write failed',
          { event_id: event.stripe_event_id, error: ex.message }
        nil
      end

      def unindex!(stripe_event_id) = timeline.remove_element(stripe_event_id.to_s)

      # Widening-only clamp (the ColonelAuditEvent#trim! rule, colonel_audit_event.rb:690).
      def trim_timeline!(cap = MAX_INDEXED)
        cap = [cap.to_i, MAX_INDEXED].max
        timeline.remrangebyrank(0, -(cap + 1))
      end

      def indexed_count = timeline.element_count

      # Newest first. Members deserialize back to plain Strings (Familia JSON
      # round-trip, data_type/serialization.rb:30/120).
      def recent_ids(limit:, offset: 0)
        limit = limit.to_i
        return [] if limit <= 0
        offset = 0 if offset.to_i.negative?
        timeline.revrange(offset, offset + limit - 1)
      end
    end
```

Familia facts relied on: `SortedSet#add(val, score)` (familia-2.12.0 `data_type/types/sorted_set.rb:127`), `#revrange` (:353), `#remrangebyrank` (:388), `#remove_element` (:446), `#element_count` (:27). `Horreum.dbkey(identifier, suffix = self.suffix)` (`horreum/management.rb:700`) gives the hash key `stripe_webhook_event:<id>:object` for the HMGET pipeline. `find_by_identifier` returns nil when the key is gone (management.rb:366, `check_exists: true`).

**Write point** — `apps/web/billing/lib/webhook_validator.rb:165` (`event.save` inside `initialize_event_record`). Add immediately after line 165:

```ruby
      event.save
      Billing::StripeWebhookEvent.index!(event)   # #4347: newest-first index, best-effort
```

This is the ONLY creation site in production code (verified: `grep StripeWebhookEvent.new` hits only the model doc comment and the validator; the worker at `apps/web/billing/workers/billing_worker.rb:172,191,204` only `find_by_identifier`s; the controller at `controllers/webhooks.rb:119` delegates to the validator). #### 1.2 `apps/web/billing/models/pending_federated_subscription.rb` (add after `identifier_field :email_hash`, line 48)

```ruby
    # Newest-first index (#4347): member = email_hash, score = received_at.
    # Written by .store_from_webhook (the single creation site,
    # webhook_handlers/subscription_federation.rb:298), removed on #destroy!
    # (the claim path, apps/web/auth/operations/create_default_workspace.rb:399).
    # Records expire after 90 days independently; readers skip + lazily unindex
    # stale members. No PII: the member is the one-way hash the record is keyed by.
    class_sorted_set :timeline
    MAX_INDEXED = 5_000

    class << self
      def index!(pending)
        timeline.add(pending.email_hash, pending.received_at.to_i)
        trim_timeline!
      rescue StandardError => ex
        Onetime.billing_logger.warn '[PendingFederatedSubscription] timeline index write failed',
          { hash_prefix: pending.email_hash.to_s[0, 8], error: ex.message }
        nil
      end
      def unindex!(email_hash) = timeline.remove_element(email_hash.to_s)
      def trim_timeline!(cap = MAX_INDEXED)
        cap = [cap.to_i, MAX_INDEXED].max
        timeline.remrangebyrank(0, -(cap + 1))
      end
      def indexed_count = timeline.element_count
      def recent_hashes(limit:, offset: 0)
        limit = limit.to_i
        return [] if limit <= 0
        offset = 0 if offset.to_i.negative?
        timeline.revrange(offset, offset + limit - 1)
      end
    end

    # Claim consumes the record (create_default_workspace.rb:399); keep the
    # index honest at the same moment. super first: if the delete raises the
    # member stays and the lazy reader cleanup catches it later.
    def destroy!
      result = super
      self.class.unindex!(email_hash)
      result
    end
```

Write point — `store_from_webhook` line 104 `pending.save` → add `index!(pending)` on the next line (inside the class method, so bare `index!`).

#### 2.1 `lib/onetime/operations/billing/webhook_events.rb` — `Onetime::Operations::Billing::WebhookEvents`

```ruby
require_relative '../../../../apps/web/billing/models/stripe_webhook_event'  # 4 levels up = Onetime::HOME (safe: webhooks_replay_command.rb:7 requires it the same way at CLI load)

class WebhookEvents
  STATUSES         = %w[pending success failed retrying].freeze
  DEFAULT_PER_PAGE = 50
  MAX_PER_PAGE     = 100
  HYDRATE_BATCH    = 500
  ERROR_PREVIEW    = 200   # list rows carry a truncated error_message; detail carries up to ERROR_MAX
  ERROR_MAX        = 2_000

  Result = Data.define(:events, :total_count, :page, :per_page, :total_pages,
                       :stale_count, :indexed_total, :event_type, :status)

  def initialize(page: 1, per_page: DEFAULT_PER_PAGE, event_type: nil, status: nil)
    # clamp exactly as StripeOrganizations#initialize (lines 93–100); status must be in STATUSES or nil (raise ArgumentError — the logic adapter has already 422'd it)
  end

  def call
    indexed_total = Billing::StripeWebhookEvent.indexed_count
    if filters?
      ids   = Billing::StripeWebhookEvent.recent_ids(limit: Billing::StripeWebhookEvent::MAX_INDEXED)   # fixed bound: the set is trimmed on every write
      rows, stale = hydrate(ids)            # HMGET pipeline, batches of HYDRATE_BATCH
      matching = rows.select { |r| matches?(r) }
      total_count = matching.size
      page_rows = matching[(page-1)*per_page, per_page] || []
    else
      total_count = indexed_total
      ids = Billing::StripeWebhookEvent.recent_ids(limit: per_page, offset: (page-1)*per_page)
      page_rows, stale = hydrate(ids)
    end
    Result.new(events: page_rows, total_count:, page:, per_page:, total_pages: (total_count.to_f/per_page).ceil, stale_count: stale, indexed_total:, event_type:, status:)
  end

  # ONE projection for list rows, CLI rows and the detail `record` — the
  # ColonelAuditReader::FIELDS idea (colonel_audit_reader.rb:85): an explicit
  # allowlist, never the raw hash, and NEVER event_payload.
  def self.format_row(fields_hash)  # string-keyed hash of LIST_FIELDS
    {
      stripe_event_id:, event_type:, processing_status:,
      livemode: fields['livemode'] == 'true',
      first_seen_at: int_or_nil, last_attempt_at: int_or_nil, processed_at: int_or_nil, created: int_or_nil,
      attempt_count: fields['attempt_count'].to_i,
      data_object_id:, request_id:,
      error_message: truncate(fields['error_message'], ERROR_PREVIEW),
    }
  end

  # Detail projection over a loaded model (find_by_identifier). Payload is
  # summarised, not returned: size only.
  def self.format_detail(event)
    format_row(LIST_FIELDS.to_h { |f| [f, event.send(f)] }).merge(
      api_version: event.api_version,
      pending_webhooks: event.pending_webhooks.to_i,
      circuit_retry_at: int_or_nil(event.circuit_retry_at),
      circuit_retry_count: event.circuit_retry_count.to_i,
      error_message: truncate(event.error_message, ERROR_MAX),
      payload_bytes: event.event_payload.to_s.bytesize,
      retryable: event.retryable?,
      max_attempts_reached: event.max_attempts_reached?,
    )
  end

  def self.replay_command(stripe_event_id) = "bin/ots billing webhooks replay #{stripe_event_id} --yes"

  private

  # Pipelined HMGET of LIST_FIELDS per id (never HGETALL: payloads). A nil/all-nil
  # reply is a stale index member: count it, `unindex!` it, drop the row.
  def hydrate(ids)
    stale = 0; rows = []
    ids.each_slice(HYDRATE_BATCH) do |slice|
      replies = Familia.dbclient.pipelined { |p| slice.each { |id| p.hmget(Billing::StripeWebhookEvent.dbkey(id), *Billing::StripeWebhookEvent::LIST_FIELDS) } }
      slice.zip(replies).each do |id, values|
        if values.nil? || values.compact.empty?
          stale += 1; Billing::StripeWebhookEvent.unindex!(id); next
        end
        rows << self.class.format_row(Billing::StripeWebhookEvent::LIST_FIELDS.zip(values).to_h)
      end
    end
    [rows, stale]
  rescue StandardError => ex
    OT.le '[Billing::WebhookEvents] hydration failed', { exception: ex, message: ex.message }
    [[], 0]
  end
end
```

`matches?(row)`: `event_type` exact (string ==), `status` exact on `processing_status`.

# DECISIONS
1. **Index name/score**: `class_sorted_set :timeline` on both models (Receipt's `expiration_timeline` naming precedent), scored by `first_seen_at` (events) / `received_at` (pending), NOT Stripe `created` — the operator question is "what arrived here, when", and `first_seen_at` is set exactly once at the single creation site; `created` can be minutes older on Stripe retries. `MAX_INDEXED = 5_000` per the scope, trimmed with the widening-only clamp from `ColonelAuditEvent.trim!`.

2. **Write point**: `WebhookValidator#initialize_event_record` (validator.rb:165), not the controller or `ProcessWebhookEvent`. The issue/map say "the webhook controller / ProcessWebhookEvent path"; verified that neither creates the record — the validator is the only `StripeWebhookEvent.new` in production code and already guards once-per-event via `first_seen_at`. The worker (`apps/web/billing/workers/billing_worker.rb`, not `lib/onetime/jobs/workers/` as the map implies) only reads. The index write is best-effort (rescue+warn) because the record is already saved and Stripe would redeliver on a 500.

3. **Pending destroy hook**: override `PendingFederatedSubscription#destroy!` to `super` then `unindex!` — the claim path (`create_default_workspace.rb:399`) is the only destroyer; `Familia::Horreum#destroy!` (persistence.rb:877) is a plain instance method, so `super` is safe. Readers also lazily unindex, so a missed removal is self-healing.

4. **Hydration for the event list uses a pipelined HMGET of `LIST_FIELDS`, not `load_multi`**: `event_payload` is stored on the same hash and can be tens of KB; the filtered path must load up to 5,000 rows per request, which HGETALL would turn into a multi-MB read. Detail uses `find_by_identifier` (needs `payload_bytes`). Bound is fixed (the set is trimmed on write), so no `capped` flag is ever true; the schema keeps it optional to honour the frozen `PageMeta`.

5. **Filters are exact-match** (`event_type`, `status` validated against the four states → 422 otherwise). No customer filter: it would require deserialising payloads (the CLI's `matches_customer?` does exactly that) and is out of the read-only, bounded scope; the operator has `data_object_id` on every row and the CLI's `--customer` for the deep case.

6. **Audit**: only `GetWebhookEvent` records an observation (`billing.webhook_event.view`, target = event id, detail = type/status/data_object_id). The list and pending list are unaudited: rows carry event ids, types, statuses and a 12-char one-way hash prefix — none of it is customer material under the curation rule in `colonel_audit_event.rb` (~200–225), and auditing every page fetch would be exactly the chatty-by-construction pressure that rule warns about. This matches the scope text ("record_access for the detail read").

7. **Payload exposure**: detail returns `payload_bytes`, `data_object_id`, `pending_webhooks`; never the payload, never in the audit detail. `error_message` is bounded (200 chars in rows, 2,000 in detail) — it is a free-text exception message from processing and can quote Stripe error bodies.

8. **Console shape**: extend `AdminBilling.vue` with two section components and a `DetailDrawer` (per scope), no new route/nav entry. Two new components + one new store (`useAdminBillingWebhooks`) rather than growing `useAdminBilling.ts`, whose single pager is wired to the roster. Replay is a copyable CLI command in the drawer (`details.replay_command`), no button.

9. **CLI placement**: `lib/onetime/cli/billing/` (the `orgs_stripe_command.rb` precedent — "read-only views shared with the colonel API"), registered as `billing webhooks list` and `billing webhooks pending`. A `billing federation` parent was rejected: dry-cli parents need a command of their own or `bin/ots billing --help` raises (cli.rb:199–202). Existing scan-based `billing webhooks --failed/--status/--stats/--migrate` are left intact (they still cover pre-upgrade records the index does not) — only `show_help` gains two lines.

10. **Tiering**: nothing added to `destructive_actions.rb` — no mutating route. Stated explicitly so the integrator does not treat the absence as an omission.

11. **Backfill**: none, per scope. Documented in the colonel admin guide row and the section description copy ("only events received after the index shipped"). The 5-day TTL makes a backfill pointless; the 90-day pending records could be backfilled by a SCAN but the scope says no and the existing CLI can still find them.

12. **Issue premises checked**: (a) "`StripeWebhookEvent` is modeled (`stripe_webhook_event.rb:52`)" — correct. (b) "`POST /webhook` is the primary billing ingress (csrf-exempt)" — correct (`apps/web/billing/routes.txt:18`). (c) "no colonel surface shows what arrived" — correct; the only viewers are the SCAN-based `bin/ots billing webhooks` commands. (d) The map's claim that a colonel list "needs an index" is correct; the map's location of the worker (`lib/onetime/jobs/workers/`) is wrong — it is `apps/web/billing/workers/billing_worker.rb` and it never creates the record. (e) The map lists `apps/api/colonel/spec/logic/colonel/stripe_organizations_spec.rb` implicitly as a colonel logic spec; the only `stripe_organizations_spec.rb` is the op spec at `spec/unit/onetime/operations/billing/`. (f) `PendingFederatedSubscription` is NOT required by `apps/web/billing/models.rb` (only by the federation handler and `create_default_workspace.rb` via `require_relative`), so the op requires it explicitly.

13. **Familia detail**: sorted-set String members JSON-round-trip to Strings (serialization.rb:30/120), so `revrange` returns plain ids and `remove_element(id)` matches. `add`/`remove_element` call `update_expiration`, so the timeline key carries the model's TTL refreshed on write — acceptable and self-cleaning; readers tolerate both an expired index and expired members.
