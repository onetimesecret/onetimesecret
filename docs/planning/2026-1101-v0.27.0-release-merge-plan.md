## 3. Sequence

### Step 1. Sync `main` into `develop` (now)

```bash
git fetch origin main develop
git checkout -b merge/v0.26.19-into-develop origin/develop
git merge origin/main
```

Expected conflicts (13 files):

- `Gemfile`, `Gemfile.lock`: keep develop's otto 2.12 floor and the
  rodauth-oauth fork; take main's sanitize 7.0.1, crass 1.0.8 and the rest of
  v0.26.19. Regenerate the lock with `bundle lock` rather than hand-merging it.
- `apps/web/auth/config/overrides/duplicate_signup.rb` (modify/delete):
  develop deleted it in favour of `account_enumeration.rb`; main changed it in
  c6d841c3c for rodauth 2.48 (load the account once through
  `_account_from_login`, because 2.47+ warns on a second load of the same
  retrieval type in one route). Port that change into `account_enumeration.rb`'s
  `new_account`, delete `duplicate_signup.rb`, reconcile
  `account_enumeration_duplicate_signup_spec.rb`.
- `apps/web/auth/config.rb`: main added a boot check that `:verify_account`
  loading agrees with `Onetime.auth_config.verify_account_loaded?`; develop
  added `::Auth::JsonMode.configure(self)`, which must run after all hooks.
  Keep both, with `JsonMode.configure` last.
- `apps/web/auth/config/hooks/account.rb`, two hunks. The first is comments
  only; keep both. The second is semantic: main guards the Redis-only
  duplicate check with `leftover.nil? &&` (closure cleanup, #4819 and #4830),
  and develop turns the same branch into the M-2 generic-success answer. The
  result needs main's guard and develop's body. It is security-relevant:
  run the account-enumeration and closure specs on it.
- `lib/onetime/logic/base.rb`: main added `ip_match` (#4757); develop added
  `route_params:` (otto 2.12). Keep both.
- `lib/tasks/spec.rake`, `tests/lanes/ownership`, `spec/unit/lanes/ownership_spec.rb`,
  `spec/unit/lanes/rspec_reporting_spec.rb`,
  `tools/testsuite/ci-auth-gating-test.sh`: both sides added lanes and files.
  Union, then `tests/lanes/run --list` and `bin/testsuite run`.
- `locales/content/en/workspace-domains.json`: one hunk, union.

Result: the Gemfile conflict was main's new rodauth fork (2.48.0, a git
source) against develop's plain `rodauth ~> 2.0`; both forks are kept.
`duplicate_signup.rb` needed no port (develop's `new_account` never loads by
login). Two conflicts showed only in the lanes: main's #4819
`DEPENDENT_TABLES` spec requires develop's `oauth_grants` and
`oauth_applications`, and main's colonel re-auth spec assumed
`path_traversal: false`, which develop's test config turns on.

All 16 Ruby lanes, vitest and the static checks pass on the result (#4882).
bundler-audit stays red there until rack 3.2.8 (#4883) is in.

Open the branch as a PR into `develop` with the #4818 body shape: merge SHA,
conflicts and how each was resolved, anything the tag removed that develop
still references, checks run. bundler-audit going green on this PR is the
sanitize check.

## 6. Operator callouts for the Deployment Notes

Drafted from PR bodies and fragments. Verify each against the merged tree
before publishing.

- Colonel, admin and staff accounts need mailbox-proof provenance (#4754). Run
  `bin/ots customers doctor` before deploying; re-verify affected accounts with
  `bin/ots customers verify EMAIL`.
- Tenant SSO creates accounts only for addresses inside a custom domain the
  organisation has TXT-verified (#4755). Tenants whose users sign in with
  another domain add and verify it first. Existing accounts keep signing in.
- Full mode runs auth migrations 012 to 014 at boot (OAuth tables) whether or
  not `AUTH_OAUTH_ENABLED` is set.
- Referrer-Policy is `strict-origin` on every response and document. Fixes the
  403 on the SSO form POST that `no-referrer` produced.
- API: burn requires `"continue": true` and answers 422 without it (#4879); a
  JSON body no longer overrides a path identifier and is ignored on GET and
  HEAD (otto 2.12). The public API quick start needs updating.
- Rollback in full mode is not a tag swap (§5).
- `bin/ots domains create` loses `--cert` and `--no-cert`; the provider
  virtual host is created at verification (#4800).
- The bundle includes a git-sourced gem (rodauth-oauth fork at a pinned SHA).
  The image build already installs git; anyone vendoring the bundle offline
  needs that checkout.
- New keys, all off or dev-only by default: `AUTH_OAUTH_ENABLED`,
  `OAUTH_ISSUER`, `OAUTH_JWT_RSA_PRIVATE_KEY`, `OAUTH_VALID_URI_SCHEMES`,
  `OAUTH_SP_DEV_*`, `SECRET_VARIABLE_NAMES`.
