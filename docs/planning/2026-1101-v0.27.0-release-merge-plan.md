## 5a. Open decisions for the maintainer

Raised 2026-11-04 by the triage of the remaining PRs. Each needs the
maintainer's call; the agent's recommendation is marked.

- **#4892** (provenance for login-recreated customers). Defer to v0.27.1
  (recommended): `main`'s recreate path stamps no provenance, which is
  fail-closed and already covered by #4754's upgrade note. Including it needs
  a branch update, a fix round (the verify-account predicate, held SSO
  accounts coming back verified) and a choice on its "email" arm, which
  derives mailbox proof from today's config and so widens access relative to
  `main` (operator approval).
- **#4908** (hold queued mail while the mail backend cannot be built).
  Including it keeps emails that would otherwise be dead-lettered, which
  matters because #4890 makes an unrecognized `SMTP_AUTH` with credentials a
  hard error in v0.27.0. Costs: a 15-second retry loop, a queue with no limit,
  no dead-letter alert, a late 24-file change with no CI run yet. Deferring
  ships the dead-letter behaviour with a deployment note.
- **OAuth IdP `email_verified`** (develop). `email_verified` is true for every
  account whose Rodauth row is Verified, which includes every SSO-created
  account, among them the ones #4754 holds unverified. Off by default
  (`AUTH_OAUTH_ENABLED`). Recommended: derive it from
  `Customer#mailbox_verified?` before the promotion (narrows the claim).
- **Account pre-hijacking.** An address owner who follows a verification link
  for an account someone else created with their address verifies that
  account with the creator's password, and #4754 runs the pending federation
  claim at verification. `develop`'s generic duplicate-signup answer no
  longer resends the link. Recommended: an issue and a v0.27.1 fix (for
  example, set the password at verification).

- Colonel, admin and staff accounts need mailbox-proof provenance (#4754). Run
  `bin/ots customers doctor` before deploying; re-verify affected accounts with

- Tenant SSO creates accounts only for addresses inside a custom domain the
  organisation has TXT-verified (#4755). Tenants whose users sign in with
  another domain add and verify it first. Existing accounts keep signing in.
  On TXT-strategy installs a domain counts only with a recorded TXT pass: run
  `bin/ots domains verify --all` after deploying (or wait for
  `DomainRefreshJob`).
- `SMTP_AUTH` is honored for SMTP delivery (#4890). `SMTP_AUTH=login` moves
  from PLAIN to LOGIN, and an unrecognized value with SMTP credentials set now
  fails delivery instead of falling back to PLAIN. Check it before upgrading.
- Full mode runs auth migrations 012 to 014 at boot (OAuth tables) whether or
  not `AUTH_OAUTH_ENABLED` is set.
- Referrer-Policy is `strict-origin` on every response and document. Fixes the
  403 on the SSO form POST that `no-referrer` produced.
- API: burn requires `"continue": true` and answers 422 without it (#4879); a
  JSON body no longer overrides a path identifier and is ignored on GET and
  HEAD (otto 2.12). The public API quick start needs updating.
- Rollback in full mode is not a tag swap (§5).
- `bin/ots domains create` loses `--cert` and `--no-cert`; the provider
