### 1.1 `lib/onetime/jobs/job_run.rb` — `Onetime::Jobs::JobRun` (plain Redis hash module, NOT a Horreum)

One hash per job: key `jobs:run:<job_id>`; one hash for the scheduler process: `jobs:scheduler`. Raw string values (no Familia JSON serialization — see decisions). All writers are best-effort: every public writer wraps its body in `rescue StandardError => ex; Onetime.get_logger('Scheduler').warn(...)` and returns nil; a job must never fail because its run record could not be written.

```ruby
module Onetime
  module Jobs
    module JobRun
      module_function
      KEY_PREFIX     = 'jobs:run'
      SCHEDULER_KEY  = 'jobs:scheduler'
      STATUSES       = %w[running success error skipped].freeze
      NEVER          = 'never'
      MAX_ERROR_LENGTH = 300
      HEARTBEAT_INTERVAL = 60          # seconds; scheduler_command refreshes heartbeat_at at this cadence
      ALIVE_WINDOW       = 3 * HEARTBEAT_INTERVAL

      def dbclient = Familia.dbclient
      def key(job_id) = "#{KEY_PREFIX}:#{job_id}"

      # job_id derivation — the ONE rule, shared with Registry: class basename minus the
      # trailing "Job", snake_cased. HeartbeatJob → heartbeat, ParticipationGCJob → participation_gc,
      # EntitlementMaterializeJob → entitlement_materialize.
      def job_id_for(klass_or_name)
        base = klass_or_name.to_s.split('::').last.sub(/Job\z/, '')
        base.gsub(/([A-Z]+)([A-Z][a-z])/, '\1_\2').gsub(/([a-z\d])([A-Z])/, '\1_\2').downcase
      end

      # Written by ScheduledJob.cron/every/in_time/at_time right after rufus returns the job.
      def register(job_class, kind:, expression:, next_time: nil)
        write(job_id_for(job_class),
          job_class: job_class.name, schedule_kind: kind.to_s, schedule_expression: expression.to_s,
          registered_at: now, next_time: epoch(next_time), scheduler_host: host, scheduler_pid: Process.pid)
      end

      def started(job_id)             # last_status running, last_started_at now, INCR run_count
      def finished(job_id, status:, duration_ms:, error: nil, next_time: nil)
        # last_status, last_finished_at, last_duration_ms, next_time (when given), last_error (class + message[0,MAX] or '' on success), INCR error_count when status == 'error'
      def read(job_id)                # hgetall → symbol-keyed hash with integer coercion for *_at / next_time / run_count / error_count / last_duration_ms / scheduler_pid; nil when the hash is absent
      def read_many(job_ids)          # one pipelined HGETALL batch → { job_id => hash|nil }
      def scheduler_started!(job_count:)  # HSET jobs:scheduler started_at, heartbeat_at, host, pid, job_count
      def scheduler_heartbeat!            # HSET heartbeat_at now
      def scheduler                       # hgetall + alive: (now - heartbeat_at) <= ALIVE_WINDOW ; nil fields when absent
    end
  end
end
```
`write(job_id, **fields)` = `dbclient.hset(key(job_id), fields.transform_keys(&:to_s).transform_values(&:to_s))`; `INCR` via `dbclient.hincrby`. `now` = `Familia.now.to_i`; `epoch(t)` = `t.respond_to?(:to_i) ? t.to_i : nil` (rufus `EoTime#to_i` works). `host` = `Socket.gethostname`. No TTL on either key (17 tiny hashes).

def cron(scheduler, pattern, **, &)
  job = scheduler.cron(pattern, **) { |rufus_job, _time| safely_execute(rufus_job, &) }

private
def safely_execute(rufus_job = nil)
  job_id = JobRun.job_id_for(self)
  JobRun.started(job_id)
  started = Process.clock_gettime(Process::CLOCK_MONOTONIC)
  result  = yield
  status  = (result.is_a?(Hash) && (result[:skipped] || result[:aborted])) ? 'skipped' : 'success'
  JobRun.finished(job_id, status: status, duration_ms: elapsed_ms(started), next_time: rufus_job&.next_time)
  result
rescue StandardError => ex

`call`: `entry = Catalog.find(@chore)`; `job_id = "chore.#{@chore}"`; `JobRun.started(job_id)` (live only); dispatch on `entry[:kind]`:

- `'billing'` (`entitlement_materialize`): dry_run → `Billing::Operations::MaterializePlans.call(include_memberships: true, dry_run: true, limit: @limit)` (NO catalog pull on a preview — a preview must not write the plan cache; `try/unit/colonel/dry_run_side_effects_try.rb` asserts previews create no keys) → preview observation with `would_materialize: result.scanned - result.skipped_no_plan` → `:dry_run`. live → `report = Onetime::Jobs::Scheduled::Maintenance::EntitlementMaterializeJob.perform(limit: @limit)` (see 3.3): `report[:skipped]` → `:skipped`; `report[:aborted]` → `:aborted`; else `:success`.

# DECISIONS
1. **Issue premise is wrong about where message-id lookup lives.** The issue says "the underlying op already supports `message_id` lookup (`replay_dlq.rb:29–34`)". Those lines are `ReplayDlq#process_params` (queue/count/dry_run only). The lookup is `Onetime::Operations::Dlq::Show#initialize(message_id:, index:)` (`lib/onetime/operations/dlq/show.rb:29–34`) → `Store.find_message` (`store.rb:161–183`), which is read-only and CLI-only. `Dlq::Replay` has no per-message path; this blueprint adds one.

2. **Scope premise is wrong about an "existing DLQ view".** There is none: `src/schemas/api/internal/responses/colonel-queue.ts:5–6` and `registry.ts:54–57` record that the DLQ console screen was removed by design review; the only queue UI is the read-only metrics table in `AdminSystem.vue:178–215`. Decision: a NEW `/colonel/jobs` screen (`AdminJobs.vue`, nav key `jobs`, group `platform`, icon `clock`) hosts scheduler + DLQ (list → peek drawer → per-message inspect/replay/discard) + chores. `AdminSystem.vue` is left untouched — its header contract says "nothing here mutates" and it is already five independent read-outs.

3. **Job count is 16, not 17.** `lib/onetime/jobs/scheduled/` has 9 files, `scheduled/maintenance/` has 7. Tests assert 16.

4. **JobRun is a plain Redis-hash module, not a Familia Horreum.** Key `jobs:run:<job_id>` (as the scope literally names it) written via `HSET`/`HINCRBY` with raw strings. Reason: Familia `save` writes every declared field (nil → `"null"`, the documented HSETNX trap) and JSON-serializes values, which breaks `HINCRBY` on `run_count` and partial updates from the scheduler; a Horreum buys nothing here (no index, no TTL, 17 keys). `Familia.dbclient` keeps it on the same DB as every other model.

5. **Registry uses `ScheduledJob.inherited` tracking, not `ObjectSpace`.** Same concrete filter as `scheduler_command.rb:97–100` (`method(:schedule).owner != ScheduledJob.singleton_class`), but deterministic and cheap in the web process. `scheduler_command#load_scheduled_jobs` is rewired to it so there is one discovery; `try/jobs/scheduled_job_discovery_try.rb` is unaffected (it re-implements the ObjectSpace query itself). Requiring `lib/onetime/jobs/scheduled/**/*_job.rb` in the web process is side-effect-free — every file only `require_relative`s `../scheduled_job`, `../queues/config`, `../publisher`, `../workers/job_lifecycle` and defines a class.

6. **"Enabled" is not derived from config.** Each job checks a differently-keyed private flag inside `schedule` (e.g. `heartbeat_enabled`, `jobs.dlq_monitor_enabled`, `jobs.maintenance.<key>.enabled`), and a disabled job simply returns before `cron/every`, so it never writes `registered_at`. The catalog reports `state: scheduled | not_scheduled | unknown` by comparing `registered_at` against the scheduler's `started_at` — the truth of the running process, not a re-implementation of 16 config lookups.

7. **`skipped` status comes from the block's return value.** `MaintenanceJob.with_stats` runs inside `safely_execute` and returns `report`; `report[:skipped]`/`[:aborted]` (set by `EntitlementMaterializeJob`) marks the run `skipped`. No change to `with_stats`; no second write path.

8. **Scheduler liveness is a separate `jobs:scheduler` hash with a 60 s heartbeat** written by a raw rufus job in `scheduler_command` (not a `ScheduledJob`, so it never lists itself). `alive` = heartbeat within 180 s. Without this, "is it alive?" is unanswerable when every job is disabled.

9. **Confirmation token for per-message replay/discard is the short queue name**, not the message id: consistent with `ReplayDlq`/`PurgeDlq` (`confirm_with: queue`, "a queue has no second identifier"), and retyping a UUID is hostile UX with no security gain. The URL `:queue` segment and the header must be the same string.

10. **`GET .../messages/:message_id` records one `record_access` observation (`queue.dlq.inspect`)** although `GetDlqMessages` (peek) records none: peek returns a 200-char preview; inspect returns the full payload, which for `dlq.email.message` carries a customer's address. Same rule the scope applies to #4347's webhook detail read.

11. **Not-found on a live replay/discard writes an operator-trail event with `outcome: 'not_found'`** (not fail-closed), mirroring #4337's no-change rule: the operator fired the verb; whether a consumer drained the message first must not hide the attempt. Discard's found path is `fail_closed: true` (purge.rb:114–117 reasoning: the message is gone and was never mirrored).

12. **`Dlq::Replay` gains `reason:` and the bulk `ReplayDlq` adapter now passes it.** The op did not accept `reason:` and the adapter never read `operator_reason_param` — a #4338 gap. Every detail goes through `with_reason`, so absent-reason shapes stay byte-identical (existing sweep expectations hold). `Replay::Result` gains `message_id`/`found` members; only replay.rb constructs it.

13. **Chore allowlist = `HousekeepingJob.models_with_chores` (as `housekeeping.<model>`) + `entitlement_materialize`.** `Org::Reconcile` is excluded (already routed). `billing catalog pull/push/sync` are excluded: push writes Stripe products and is not a convergence chore.

14. **Chore runs are synchronous and bounded by `limit` (default 500, max 5000), never enqueued** — no worker exists for chores. `MaterializePlans` gains a `limit:` kwarg (it iterates `Organization.instances`, which on prod is ~200k rows — unbounded sync HTTP is not acceptable). The response carries `capped` and the CLI command string; the full-fleet run stays a CLI job.

15. **Housekeeping chores cannot dry-run** (`do_chore!` writes unconditionally), so their preview is "would scan N" only. `entitlement_materialize` preview runs `MaterializePlans(dry_run: true)` and deliberately SKIPS `Catalog::Pull` (a preview must create no keys — `try/unit/colonel/dry_run_side_effects_try.rb` contract); the live path keeps the job's fail-closed pull gate by calling the job's newly-public `perform(limit:)`.

16. **`RunChore` is tier 2 (`:sensitive`)**, confirmation = the chore id, no destructive budget. `ReplayDlqMessage` tier 2; `DiscardDlqMessage` tier 1 with `network=admin_if_configured` — per the scope, and both annotation specs enforce it.

17. **No new chore CLI.** `bin/ots housekeeping run` and `bin/ots billing plans materialize` already exist; the console shows the equivalent command. (Those CLI paths remain unaudited today — out of scope, note in PR.)

18. **`bin/ots scheduler status` coexists with the `scheduler` leaf command** — `register 'audit'` + `register 'audit list'` (`audit_command.rb:214–215`) is the precedent. It boots the app without starting rufus and reads the same `JobRun.catalog` projection the HTTP endpoint uses.

19. **Queue pause/drain (item 4) is deferred**, per the scope: no consumer-cancel or queue-level flag primitive exists; a cross-process pause needs #4340's maintenance-posture design.
