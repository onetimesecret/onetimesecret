Added
-----

- SAML 2.0 single sign-on, on both surfaces. Platform: set
  ``SAML_IDP_SSO_SERVICE_URL``, ``SAML_IDP_ENTITY_ID`` and ``SAML_IDP_CERT``
  (the IdP's PEM signing certificate; fingerprints are not accepted) and
  register ``https://<host>/auth/sso/saml/metadata`` as the SP EntityID and
  ``https://<host>/auth/sso/saml/callback`` as the ACS URL at the IdP.
  Per-domain: a custom domain's SSO configuration accepts provider type
  ``saml`` with the same three fields, shows the SP identifiers to register,
  and validates them locally through "Test connection" without contacting the
  IdP. Every response must answer the sign-in request this site issued
  (IdP-initiated sign-in and single logout are not supported), assertions are
  single-use, and the response Issuer must equal the configured EntityID
  exactly. Per-domain identities are keyed on the EntityID scoped to the
  domain that pinned the certificate, so a domain cannot reach another
  domain's (or the platform's) identities by configuring their EntityID with
  its own certificate. Requires ``site.session.same_site: none`` with ``secure: true``,
  like Sign in with Apple. Missing or unusable ``SAML_*`` values skip the
  provider with an error in the boot log rather than failing boot. (#4450)

Changed
-------

- When org-level SSO is enabled and a platform provider's environment
  variables are present but unusable (Auth0, Apple, SAML), the tenant
  placeholder route is now registered as if the variables were absent,
  instead of no route at all; the platform button stays hidden. A
  platform-side typo can no longer remove the route that per-domain SSO
  injects into. (#4450)

- The SSO ``email_verified`` hold now recognises an array-valued claim, which
  is how SAML attributes arrive: any ``false`` among the values leaves the
  account unverified with an ``idp_unverified`` hold. (#4450)

Security
--------

- ``ruby-saml`` is pinned exactly in the Gemfile with its advisory history,
  and a ``bundler-audit`` job runs against ``Gemfile.lock`` on every pull
  request. (#4450)

Documentation
-------------

- Operator guides for platform and per-domain SAML
  (``docs/authentication/per-install-sso.md``, ``per-domain-sso.md``), the
  SAML entry in the provider-registration checklist, and ADR-044 recording
  SAML as the reference case for its "OIDC is unavailable" criterion.
  (#4450)
