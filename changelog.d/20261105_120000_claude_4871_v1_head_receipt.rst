Security
--------

- The v1 API now answers ``HEAD`` on ``/api/v1/receipt/:key`` and its
  ``/private/:key`` and ``/metadata/:key`` aliases with
  ``405 Method Not Allowed`` and an ``Allow`` header. Before, ``HEAD`` ran
  the ``GET`` handler, so a link preview or scanner could use up the
  creator's one-time view of a generated secret. ``GET`` is unchanged. The
  v2 and v3 receipt and secret routes refuse ``HEAD`` the same way. (#4871)
